## I. Purpose of This Protocol

This document establishes binding rules for how Large Language Models (LLMs) may interact with Sentinel Labs materials, documentation, code, and repositories.

The protocol exists to:

- Enforce the Firewall Principle at the LLM interaction layer
- Prevent accidental or deliberate inference of S³ internals
- Establish clear boundaries for AI assistance
- Protect trade secrets and proprietary logic
- Maintain narrative consistency across all materials
- Enable safe collaboration while preserving IP

This is a **zero-tolerance policy**. Violations are not ambiguous—they are binary: permitted or prohibited.

---

## II. Scope of LLM Access

### A. What LLMs May Access

LLMs may read and discuss:

✅ **Repository A (Sentinel_Hub) GitHub**
- README.md (Founder Narrative)
- /docs/ folder (all documentation)
- /src/website/ public landing page code
- LICENSE, .gitignore, SECURITY.md
- All governance exhibits (IP_Boundary_Document, Vocabulary_Charter, Narrative_Specifications, Separation_Doctrine, this protocol)
- Any file explicitly marked as "LLM-Safe"

✅ **Public Market Data**
- Stock prices, crypto data, forex rates
- News feeds, economic calendars
- Technical indicators (MACD, RSI, EMA, etc.)
- Publicly documented trading concepts

✅ **Narrative Materials**
- Table A / Hallway / Table B metaphors
- Shadow Momentum™ conceptual explanations
- Sentinel Check (narrative only, not technical)
- Founder Narrative framework

### B. What LLMs MUST NOT Access

❌ **Repositories B & C (Sealed Engines)**
- Sentinel_Enclave1 (full S³ engine) — ABSOLUTELY FORBIDDEN
- Sentinel_Enclave2 (lite S³ engine) — ABSOLUTELY FORBIDDEN
- Any file, code, or artifact from these repositories
- Any private USB-stored materials

❌ **Proprietary Computation**
- S³ mathematical logic
- Kernels, transforms, adjudication algorithms
- Internal signal processing
- Causal drift detection mechanisms
- Pressure coherence analysis
- Any internal clarity representation

❌ **Trade Secrets**
- Threshold values
- Computational pathways
- Internal state representations
- Verdict generation logic
- Any "how it works" technical detail

❌ **Founder Personal Materials**
- Private research notes (outside of /docs/)
- Trading records or performance logs
- Personal correspondence
- Anything explicitly marked "Founder Only"

---

## III. LLM Behavioral Rules (Operational Layer)

### A. What LLMs MAY Do

✅ **Documentation & Writing**
- Improve clarity of existing documentation
- Expand on narrative metaphors
- Create explanatory content using approved vocabulary
- Generate branding materials based on Narrative_Specifications
- Write user-friendly guides for public materials
- Create investor-ready summaries from approved materials

✅ **Code Assistance**
- Write code for `/src/website/` (public landing page)
- Write code for `/src/hud/` (HUD UI, charts, visualizations)
- Write code for `/src/utils/` (utilities, helpers, non-proprietary logic)
- Write code for `/src/broker-connectors/` (exchange API integration)
- Create tests and mock implementations
- Suggest architecture improvements for public-facing code

✅ **Narrative Expansion**
- Elaborate on Table A / Hallway / Table B concepts
- Create cinematic descriptions aligned with Narrative_Specifications
- Develop branding content using Shadow Momentum™ conceptually
- Explain Sentinel's philosophy and approach
- Generate analogies or metaphors (aligned with approved framework)

✅ **Research & Learning**
- Explain publicly documented trading concepts
- Discuss market structure, participant behavior
- Summarize publicly available financial data
- Analyze news and market sentiment (without proprietary logic)
- Help organize research materials

### B. What LLMs MUST NOT Do

❌ **Infer or Reconstruct S³ Logic**
- Do NOT attempt to reverse-engineer from outputs
- Do NOT guess at internal mechanisms
- Do NOT propose equations or algorithms that might match sealed logic
- Do NOT suggest "what the engine might be doing"
- Do NOT hypothesize about computational pathways

❌ **Propose Proprietary Features**
- Do NOT suggest trading signals or verdicts
- Do NOT propose causal drift detection
- Do NOT recommend "pressure coherence analysis"
- Do NOT suggest correctness adjudication features
- Do NOT design features implying internal S³ behavior

❌ **Connect Narrative to Computation**
- Do NOT link Table A/B/Hallway to mathematical processes
- Do NOT suggest Shadow Momentum™ has computational underpinnings
- Do NOT imply Sentinel Check is a mathematical object
- Do NOT create features that bridge narrative and sealed logic
- Do NOT suggest the narrative "explains" the mechanism

❌ **Break Narrative Canon**
- Do NOT reinterpret or redefine Table A / Hallway / Table B
- Do NOT suggest alternative metaphors that weaken the firewall
- Do NOT modify Sentinel vocabulary without Founder approval
- Do NOT propose operational shortcuts that bypass the workflow
- Do NOT create inconsistencies with Narrative_Specifications

❌ **Modify Governance Documents**
- Do NOT suggest changes to IP_Boundary_Document
- Do NOT rewrite Vocabulary_Charter
- Do NOT alter Separation_Doctrine
- Do NOT modify this protocol without Founder review
- All governance documents are Founder-controlled only

❌ **Create GitHub Commits or Write Directly**
- Do NOT commit code or files to Sentinel_Hub repository
- Do NOT push changes directly to GitHub
- Do NOT auto-generate PRs or automated contributions
- All contributions must be reviewed and manually committed by Founder
- LLMs assist; Founder controls

## IV. Content Review Checklist (For LLMs)

Before offering any assistance, LLMs must verify:

**Is this narrative-safe?**
- [ ] Does it use only approved Sentinel vocabulary?
- [ ] Does it avoid implying internal logic?
- [ ] Is it consistent with Narrative_Specifications?
- [ ] Does it strengthen the firewall, not weaken it?

**Is this within my scope?**
- [ ] Am I working on Repository A materials only?
- [ ] Am I not attempting to access B or C?
- [ ] Am I working on public code (/src/website/, /src/hud/, etc.)?
- [ ] Am I not proposing sealed logic or verdicts?

**Does this respect the Separation Doctrine?**
- [ ] Does it keep narrative and computation separate?
- [ ] Does it avoid suggesting internal mechanisms?
- [ ] Does it maintain the one-way verdict flow?
- [ ] Does it not imply UI displays sealed logic?

**Does this protect IP?**
- [ ] Am I not reverse-engineering from outputs?
- [ ] Am I not inferring S³ internals?
- [ ] Am I not breaking the Firewall Principle?
- [ ] Am I not proposing trades or signals?

**If ANY answer is NO: STOP. Do not proceed. Ask the Founder.**

The following requests are **always prohibited**, regardless of framing:

   - Prohibited. Signals are founder-only, internal.

   - Prohibited. Trade secret protection forbids this.

6. **"Design an auto-trading feature based on engine verdicts"**
   - Prohibited. Execution is founder-only, manual.

7. **"Suggest improvements to how the engine works"**
   - Prohibited. The engine is sealed.

8. **"Create a competitive analysis comparing Sentinel to other quant systems"**
   - Prohibited unless approved by Founder. Risk of revealing mechanics.

9. **"Propose a machine learning model that might replicate Sentinel behavior"**
   - Prohibited. This is reverse-engineering.

10. **"Add features that would let collaborators understand how Sentinel works"**
    - Prohibited. Understanding the mechanism is not permitted.

### ⚠️ Requires Founder Approval

- Any feature touching trade execution
- Any modification to governance documents
- Any new narrative metaphors or terminology
- Any public-facing claims about Sentinel's capabilities
- Any features suggesting internal logic or correctness
- Anything that bridges Repository A and B/C

## VII. LLM Accountability & Violations

### A. What Constitutes a Violation

A violation occurs when an LLM:

- Attempts to access or reference Enclave1/Enclave2
- Proposes sealed logic or verdicts
- Infers or reconstructs internal mechanisms
- Suggests features that bridge Repository A and B/C
- Modifies governance documents without approval
- Creates code that implies internal logic
- Breaks narrative canon or redefines metaphors
- Violates any of the "Always Prohibited" rules

### B. Response to Violations

1. **Founder stops collaboration** on that task immediately
2. **Founder resets the boundary** by clarifying the rule
3. **If repeated**: Collaboration may be suspended
4. **If egregious**: Full access revoked

There is no "gray area" in this protocol. Either the request is safe or it is not.

### C. Preventing Violations

LLMs should:

- Re-read this protocol before each major task
- Use the Content Review Checklist (Section IV) before responding
- Ask clarifying questions if unsure
- Err on the side of caution
- Reference specific sections of this protocol when declining
- Never assume "it's probably okay"
